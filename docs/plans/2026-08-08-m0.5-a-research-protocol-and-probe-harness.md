## Secret Handling

- `CHAPA_SECRET_KEY` is read only from process environment when a future credential-requiring probe runs.
- No hardcoded credential.
- No fallback/default secret.
- Fail closed if a credential-requiring path runs without the credential.
- Never print the credential.
- Never serialize `Authorization` values.
- Never include `Authorization` in captured request metadata.
- Never include secrets in thrown error text.
- Never put secrets in filenames.
- Never commit secrets.
- Never include provider-secret-derived signatures in committed fixtures.
- No secret in Git history.

Request observation must use an explicit SAFE ALLOWLIST (no "capture everything, redact afterward" for headers). No credential is needed or authorized for M0.5-A local validation.

## Raw Capture Boundary

A dedicated local-only raw evidence path: `research/contract-probes/.raw/`
It must:
- Be added to `.gitignore` BEFORE the first M0.5-B provider probe.
- Remain local only.
- Never be staged or committed.
- Never be pasted into PRs or agent handoffs.
- Never contain `Authorization` values.
- Be treated as ephemeral provider evidence.

M0.5-A creates no provider raw capture. The implementation will include a test proving the `.raw/` directory is actually ignored by Git before M0.5-A is complete.

## Request Execution Contract

Future request executor rules:
- Node built-in `fetch`/HTTP only.
- Built-in `fetch` uses `redirect: 'manual'`.
- A 3xx response is captured as the single HTTP response for that invocation.
- The harness never automatically follows `Location`.
- Any deliberate follow-up request is a separate invocation.
- Redirects cannot bypass the one-network-attempt rule.
- Exactly ONE network attempt per invocation.
- No retry middleware; no hidden retry.
- Explicit bounded timeout using `AbortController` (or equivalent built-in mechanism).
- `attemptCount = 1`.
- Method recorded.
- Path/URL recorded safely.
- `Authorization` never recorded.
- Request body capture must avoid secret/PII leakage.
- HTTP status captured.
- Response body retained accurately for local evidence where appropriate.
- Response headers recorded only through an explicit safe allowlist.
- Transport timeout/error distinguished from HTTP response.
- Uncertain mutation result is not interpreted as provider failure.

Local test:
- Endpoint A returns 302 pointing to endpoint B.
- Invoke once against A.
- A receives exactly one request.
- B receives zero requests.
- The 3xx response is captured.

*Note: This is the research harness policy only; it does not alter the future production SDK GET retry policy.*

## Raw Response-Byte Capture

The primary response observation must preserve:
- HTTP status;
- allowlisted response headers;
- exact response body bytes;
- duration;
- `attemptCount = 1`.

Requirements:
- Body consumed using `arrayBuffer()` or equivalent.
- UTF-8 decoding or JSON parsing happens only as a derived step.
- Parsing must never replace or mutate the original bytes.

Add a local byte-for-byte test.

## Response Header Policy

Use an explicit allowlist. Do not persist every response header automatically.
Initial safe candidates:
- `content-type`
- An observed provider request/correlation identifier (only if useful and safe).
- Other specifically reviewed non-sensitive headers.

OQ-06 remains unresolved/observational. Do NOT invent a Chapa request-ID header. Unknown headers must not automatically enter sanitized fixtures.

## Sanitization Workflow

Sanitization must be a distinct stage from raw capture.
The workflow must:
- Read local raw evidence.
- Produce a candidate sanitized artifact.
- Never overwrite raw evidence automatically.
- Remove secrets, PII, and provider signatures derived from actual test/live secrets.
- Replace unnecessary provider-generated identifiers.
- Replace sensitive values with safe fictional/redacted values when retaining the key/type matters.
- Preserve contract-relevant key presence.
- Preserve type and nesting where evidence depends on them.
- Preserve meaningful status values and safe contract-relevant formats.
- Do not silently drop unfamiliar fields.
- Mark output as sanitized.
- Require HUMAN REVIEW before staging.

If sanitization cannot safely preserve evidence, escalate for human review. Do not produce a stage-ready artifact in that case.
Sanitized output remains a candidate until human review. Automation never marks a fixture V. Automation may assist sanitization, but automation must NOT decide that evidence is safe to commit.

## Network-Safety Guard

M0.5-A prevents accidental provider access:
- The planned harness must parse the target URL before network execution.
- Allow only `localhost`, `127.0.0.1`, `::1` during M0.5-A validation.
- Reject all other hosts before calling fetch.
- Test `https://api.chapa.co/...` only as a rejected URL, and prove rejection occurs before any network attempt.
- No Chapa execution command is authorized.
- No internet connectivity is required.
- No credential is required.
- Accidental external target should fail closed during local test mode.

*Do not overengineer this into production networking architecture.*

## Local Validation

The harness will be tested locally using Node built-ins (e.g. local Node `http` server). No external test service.
Minimum test plan:
1. Credential-requiring path fails closed without `CHAPA_SECRET_KEY`.
2. Secret value is never printed.
3. `Authorization` is absent from captured metadata.
4. `.raw/` directory is ignored by Git.
5. Timeout/`AbortController` behavior works locally.
6. One invocation creates exactly one request attempt.
7. Status/body capture works against loopback HTTP.
8. Allowed response headers are retained.
9. Unapproved response headers are excluded.
10. Sanitizer removes representative FICTIONAL: name, email, phone, secret, `Authorization`, provider-signature-style field.
11. Sanitizer preserves relevant field names/types/nesting.
12. Generated JSON parses.
13. No test reaches `api.chapa.co`.
14. No test requires internet connectivity.
15. No test requires a real Chapa secret.

Synthetic/local data used for testing must be explicitly identified as synthetic test data, not D/V provider evidence.
