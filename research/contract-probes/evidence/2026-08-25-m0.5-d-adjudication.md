## 1. OQ-02: Cancellation Contract

- **candidate-V**: In the exact observed Test Mode lifecycle, one no-body `PUT /v1/transaction/cancel/{tx_ref}` for a fresh initialized transaction returned HTTP 200, top-level `success`, message `Checkout link expired successfully`, and the submitted `tx_ref` in the response data.
- **candidate-V**: A separately authorized verification of the same reference after cancellation returned HTTP 200 and `data.status = "pending"`, with `data.mode = "test"`.
- **candidate-V**: Exactly one second cancellation of that same reference returned HTTP 400, top-level `failed`, message `Payment link already expired`, and `data = null`.
- **candidate-V**: One no-body cancellation using exact never-used synthetic reference `m05d_unknown_8a3f0e2c9b714d65` returned HTTP 404, top-level `failed`, message `Payment link not found`, and `data = null`.
- **U**: A universal transaction-state transition to `cancelled`. The observed verification remained `pending`; the successful cancellation envelope is treated as checkout-link expiration for this scenario.
- **U**: Stable machine-readable discriminators for already-cancelled or unknown-reference behavior. English messages and HTTP status alone are insufficient.
- **U**: Paid/non-cancellable behavior, all other transaction states/reference forms, and live-mode parity.

Automation does not promote these candidate-V observations to V. Exact sanitized observations are recorded in `2026-08-25-m0.5-d-cancellation-observations.md`.

## 4. D6 Local Contract Work

Classification: local harness/safety verification, not provider-contract evidence.

- Refund creation candidate builder: caller-supplied reviewed target only; `POST /v1/refund/{identifier}`; exact form content type.
- Refund verification candidate builder: caller-supplied reviewed `ref_id` only; bodyless `GET /v1/refund/{ref_id}/verify`.
- Strict local reference grammar is a safety allowlist and makes no claim about provider grammar.
- Refund top-level `amount`, `reason`, and `reference` are optional strings in the local research builder.
- `meta` is an optional plain object whose keys use the strict local safety grammar and whose values are strings, finite numbers, or booleans.
- Meta is encoded as deterministic bracket keys such as `meta[key]` through the canonical `URLSearchParams` form algorithm.
- Arrays, nested objects, null, undefined, non-finite numbers, unsafe keys, class instances, and unknown top-level fields are rejected.
- Duplicate output keys are structurally unavailable: top-level and meta namespaces are distinct and input objects cannot contain duplicate own keys.
- Exact origin/path/method/header/body coupling, one mutation attempt, zero retry, manual redirect, bounded timeout, secret-safe errors, and no automatic verification after uncertainty are locally tested.

These local policies do not establish Chapa's provider-side refund or meta behavior.
