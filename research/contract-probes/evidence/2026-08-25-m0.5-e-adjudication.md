# M0.5-E E5 Signature Reproduction Adjudication Note

**Status**: Candidate findings pending E7 maintainer adjudication

This note records the narrow result of one sanitized Chapa Test Mode observation. It does not amend the normative specification and contains no provider payload, signature, digest, secret, URL, or transaction identifier.

## `x-chapa-signature`

Observed Test Mode candidate:

```text
HMAC-SHA256(
  key = webhookConfiguredSecret,
  message = exact raw body bytes
)
encoding = 64-character hexadecimal syntax as observed
classification = candidate-V
```

The observed value used lowercase hexadecimal syntax. The local decoder's acceptance of uppercase hexadecimal is a local policy and does not claim the provider emits uppercase.

## `chapa-signature`

Observed Test Mode candidate:

```text
HMAC-SHA256(
  key = webhookConfiguredSecret,
  message = UTF8(webhookConfiguredSecret)
)
encoding = 64-character hexadecimal syntax as observed
classification = candidate-V
```

## Rejected candidates for this observation

- X2, using `apiSecretKey` over exact raw body bytes: false.
- C2, using `apiSecretKey` over UTF-8 bytes of `apiSecretKey`: false.

The `webhookConfiguredSecret` and `apiSecretKey` were deliberately distinct, so the observation distinguishes the tested alternatives. This does not prove that an API secret can never be used under another provider configuration.

## Raw-versus-reserialized boundary

JSON parsing succeeded. The 459-byte raw body and ordinary parse/stringify result were byte-identical and both 459 bytes. The provider distinction between exact-raw signing and an equivalent serialization is therefore unresolved for this observation. Production verification must still use exact original raw bytes under the normative specification.
